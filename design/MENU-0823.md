# 0.8.23: direct adventure setup

THESIS: Adam's clear cartoon sky world surrounds a familiar console-style launch flow. The user explicitly requested competitor-like ease and replacement of old scroll/sign menus; this commitment overrides exploratory directions (seed df11081f).
AUDIENCE: families sharing a living-room TV, plus a child playing on a phone; large readable Arabic and unambiguous focus matter more than decorative borders.
PALETTE: sky cyan owns the surface, deep teal owns text, honey gold marks chosen/primary actions, mint is a secondary surface. Lalezar display and Vazirmatn body are bundled OFL fonts.
FLOW: home → session setup → play. Setup exposes mode immediately, outfit and stage explicitly, and pace beside the start action. Secondary choices return to the same session. A single native Back policy unwinds screens; gameplay Back pauses, pause Back resumes, root Back exits normally.
PERFORMANCE: static background, shared sprite atlases, no blur or per-frame image processing. Render budget and fixed 60 Hz simulation remain intact.

Reference observations and our application (not usability study claims): Android TV's official guidance recommends fewer screens, directional focus, and returning to the previous destination. PlayStation's Sackboy page presents solo and local cooperative adventures with distinct costumes; this motivates separating session type from outfit customization rather than placing every choice on home.

Sources: https://developer.android.com/training/tv/get-started/navigation and https://www.playstation.com/en-us/games/sackboy-a-big-adventure/ . The selected clean cartoon style and Adam likeness are explicit incumbent commitments.
